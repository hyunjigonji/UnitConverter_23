# UnitConverter_23 — Product Requirements Document (PRD)

**프로젝트:** UnitConverter_23  
**문서 버전:** 1.0  
**작성일:** 2026-06-05

---

## 1. 프로젝트 개요

UnitConverter_23는 사용자가 **단위와 값**을 한 줄로 입력하면, 해당 값을 **같은 물리량(카테고리)에 속하는 모든 지원 단위**로 변환하여 출력하는 **CLI 단위 변환 프로그램**이다.

사용자는 별도 설정 없이 터미널에서 즉시 길이·무게·온도·넓이·부피 단위 간 변환 결과를 확인할 수 있어야 한다.

---

## 2. 목표

| ID | 목표 |
|----|------|
| G1 | `<unit>:<value>` 형식 입력 하나로 **동일 카테고리 전 단위** 변환 결과 제공 |
| G2 | 변환 결과가 **정확하고 결정적(deterministic)** 이어야 함 — 동일 입력은 항상 동일 출력 |
| G3 | 잘못된 입력에 대해 **명확한 오류 코드(E001~E007)** 로 사용자에게 알림 |
| G4 | 향후 단위·카테고리 추가 시에도 **요구사항 변경 없이** 확장 가능한 제품 경험 유지 |
| G5 | 모든 변환·입력 검증 동작은 **테스트로 검증 가능**해야 함 |

---

## 3. 사용자 시나리오

### US-01 — 길이 단위 변환 (정상)

**Given** 사용자가 CLI를 실행한 상태  
**When** `meter:2.5` 를 입력  
**Then** Length 카테고리의 모든 지원 단위(mm, cm, meter, km, inch, feet, yard, mile)에 대한 변환 결과가 출력된다.

**예시 출력:**

```
mm:2500
cm:250
meter:2.5
feet:8.2021
inch:98.4252
...
```

(출력 순서·포함 단위 목록은 일관되어야 하며, 입력 단위 포함 여부는 Acceptance Criteria 참조)

---

### US-02 — 무게 단위 변환 (정상)

**Given** 사용자가 CLI를 실행한 상태  
**When** `kg:1` 을 입력  
**Then** Weight 카테고리의 모든 지원 단위(mg, g, kg, oz, lb) 변환 결과가 출력된다.

---

### US-03 — 온도 단위 변환 (정상)

**Given** 사용자가 CLI를 실행한 상태  
**When** `celsius:100` 을 입력  
**Then** Temperature 카테고리의 모든 지원 단위(celsius, fahrenheit, kelvin) 변환 결과가 출력된다.

---

### US-04 — 넓이·부피 단위 변환 (정상)

**Given** 사용자가 CLI를 실행한 상태  
**When** `sqm:10` 또는 `liter:2` 를 입력  
**Then** 각각 Area(sqm, pyeong, acre, hectare) 또는 Volume(ml, liter, gallon) 카테고리 전 단위 변환 결과가 출력된다.

---

### US-05 — 빈 입력

**Given** 사용자가 CLI를 실행한 상태  
**When** 아무 것도 입력하지 않거나 공백만 입력  
**Then** **E004 EmptyInput** 오류가 보고된다.

---

### US-06 — 잘못된 입력 형식

**Given** 사용자가 CLI를 실행한 상태  
**When** `:` 가 없거나, 형식이 `<unit>:<value>` 를 따르지 않음 (예: `meter2.5`, `meter`)  
**Then** **E001 InvalidInputFormat** 오류가 보고된다.

---

### US-07 — 잘못된 숫자

**Given** 사용자가 CLI를 실행한 상태  
**When** `meter:abc` 또는 `meter:1.2.3` 처럼 값이 유효한 숫자가 아님  
**Then** **E003 InvalidNumericValue** 오류가 보고된다.

---

### US-08 — 미지원 단위

**Given** 사용자가 CLI를 실행한 상태  
**When** 지원 목록에 없는 단위를 입력 (예: `cubit:1`)  
**Then** **E002 UnsupportedUnit** 오류가 보고된다.

---

## 4. 기능 요구사항

### FR-01 — 단위 변환

| ID | 요구사항 |
|----|----------|
| FR-01-1 | 시스템은 지원 단위 목록(§6)에 정의된 단위 간 변환을 수행해야 한다. |
| FR-01-2 | 입력 단위가 속한 **카테고리의 모든 지원 단위**로 변환 결과를 출력해야 한다. |
| FR-01-3 | 다른 카테고리 단위는 출력하지 않는다. (예: `meter:2.5` 입력 시 Weight 단위 미출력) |
| FR-01-4 | 변환은 **Base Unit(기준 단위)** 를 경유하여 수행되어야 한다. |
| FR-01-5 | Temperature(celsius, fahrenheit, kelvin)는 물리적으로 올바른 변환 공식을 따라야 한다. |

**카테고리별 Base Unit:**

| 카테고리 | Base Unit |
|----------|-----------|
| Length | meter |
| Weight | g |
| Temperature | celsius |
| Area | sqm |
| Volume | liter |

---

### FR-02 — 입력 처리

| ID | 요구사항 |
|----|----------|
| FR-02-1 | 시스템은 사용자로부터 **한 줄** 입력을 받아야 한다. |
| FR-02-2 | 입력 형식은 `<unit>:<value>` 이어야 한다. |
| FR-02-3 | `<unit>` 은 영문 소문자 식별자이며, 지원 단위 목록과 **정확히 일치**해야 한다. |
| FR-02-4 | `<value>` 는 유효한 실수(정수 포함)여야 한다. |

---

### FR-03 — 출력

| ID | 요구사항 |
|----|----------|
| FR-03-1 | 정상 변환 시 **한 줄에 하나의 단위**를 `<unit>:<converted_value>` 형식으로 출력해야 한다. |
| FR-03-2 | 출력 대상은 입력 단위가 속한 카테고리의 **전 지원 단위**이다. |
| FR-03-3 | 입력 단위에 해당하는 줄도 출력에 **포함**되어야 한다. (예: `meter:2.5` → `meter:2.5` 포함) |
| FR-03-4 | 소수 출력은 **불필요한 trailing zero 없이** 가독성 있게 표시되어야 한다. (예: `250`, `8.2021`) |

---

### FR-04 — 오류 처리

| ID | 요구사항 |
|----|----------|
| FR-04-1 | 오류 발생 시 §8 오류 코드 중 **하나**를 사용자에게 전달해야 한다. |
| FR-04-2 | 오류 시 변환 결과는 출력하지 않는다. |
| FR-04-3 | E001~E007 외 임의 오류 코드·메시지를 사용하지 않는다. |

---

### FR-05 — 지원 단위

시스템은 아래 단위만 지원한다.

| 카테고리 | 지원 단위 |
|----------|-----------|
| Length | mm, cm, meter, km, inch, feet, yard, mile |
| Weight | mg, g, kg, oz, lb |
| Temperature | celsius, fahrenheit, kelvin |
| Area | sqm, pyeong, acre, hectare |
| Volume | ml, liter, gallon |

## 5. 비기능 요구사항

| ID | 요구사항 |
|----|----------|
| NFR-01 | **결정성:** 동일 입력에 대해 항상 동일 출력(오류 포함)을 보장해야 한다. |
| NFR-02 | **정확성:** 변환 결과는 업계 표준 계수·공식에 부합해야 한다. |
| NFR-03 | **확장성:** 신규 단위 추가 시 기존 사용자 시나리오·출력 형식이 깨지지 않아야 한다. |
| NFR-04 | **검증 가능성:** 모든 기능 요구사항(FR)은 자동화 테스트로 검증 가능해야 한다. |
| NFR-05 | **단일 진실 공급원(SSOT):** 변환 계수·Base Unit·단위 문자열은 중복 정의 없이 일관되어야 한다. |
| NFR-06 | **사용성:** CLI는 추가 인자 없이 실행 후 한 줄 입력만으로 동작해야 한다. |
| NFR-07 | **오류 명확성:** 오류 코드(E001~E007)만으로도 오류 유형을 구분할 수 있어야 한다. |

## 6. 입력 형식

| 항목 | 규격 |
|------|------|
| 형식 | `<unit>:<value>` |
| 구분자 | 콜론(`:`) **1개** — 첫 번째 `:` 기준 좌측=단위, 우측=값 |
| 단위(`<unit>`) | 지원 단위 식별자 (영문 소문자) |
| 값(`<value>`) | 유효한 실수; 선행·후행 공백 허용 여부는 Acceptance Criteria 참조 |
| 예시 (유효) | `meter:2.5`, `kg:1`, `celsius:0`, `liter:3.14` |
| 예시 (무효) | `` (빈 문자열), `meter`, `2.5`, `meter:`, `:2.5`, `meter:abc` |

---

## 7. 출력 형식

### 7.1 정상 출력

| 항목 | 규격 |
|------|------|
| 형식 | `<unit>:<converted_value>` |
| 줄 단위 | **한 줄 = 한 단위** |
| 범위 | 입력 단위와 **동일 카테고리** 전 지원 단위 |
| 예시 | `meter:2.5` 입력 시 |

```
mm:2500
cm:250
meter:2.5
km:0.0025
inch:98.4252
feet:8.2021
yard:2.734
mile:0.001553
```

> 위 수치는 **예시**이며, Acceptance Criteria는 형식·범위·결정성을 검증한다.

### 7.2 오류 출력

| 항목 | 규격 |
|------|------|
| 형식 | 오류 코드 식별자 (E001~E007) |
| 내용 | 해당 오류 코드에 대응하는 E00x만 출력 (변환 결과 없음) |

---

## 8. 오류 코드 (E001~E007)

| 코드 | 이름 | 발생 조건 |
|------|------|-----------|
| **E001** | InvalidInputFormat | 입력이 `<unit>:<value>` 형식이 아님 (`:` 없음, 구조 불일치 등) |
| **E002** | UnsupportedUnit | `<unit>` 이 지원 단위 목록에 없음 |
| **E003** | InvalidNumericValue | `<value>` 가 유효한 숫자로 파싱되지 않음 |
| **E004** | EmptyInput | 입력이 비어 있거나 공백만 있음 |
| **E005** | ConversionNotSupported | 지원 단위이나 변환 조합·카테고리 처리가 불가한 경우 |
| **E006** | InternalConversionError | 변환 처리 중 내부 오류 발생 |
| **E007** | UnknownError | 위 코드로 분류되지 않는 예외적 오류 |

**우선순위 (동시 해당 시):** E004 → E001 → E003 → E002 → E005 → E006 → E007

## 9. Acceptance Criteria

### AC-01 — Length 정상 변환

- **Given** 유효한 입력 `meter:2.5`
- **When** 변환을 수행
- **Then**
  - [ ] 출력 줄 수 = Length 지원 단위 수(8)
  - [ ] 각 줄 형식 = `<unit>:<value>`
  - [ ] 출력 단위 집합 = {mm, cm, meter, km, inch, feet, yard, mile}
  - [ ] `meter:2.5` 줄 포함
  - [ ] 동일 입력 재실행 시 출력 **완전 동일**

---

### AC-02 — 카테고리 격리

- **Given** `meter:2.5` (Length)
- **When** 변환을 수행
- **Then**
  - [ ] Weight / Temperature / Area / Volume 단위 **미출력**

---

### AC-03 — 카테고리별 전 단위 출력

| 입력 예 | 출력 카테고리 | 출력 단위 수 |
|---------|---------------|--------------|
| `kg:1` | Weight | 5 |
| `celsius:100` | Temperature | 3 |
| `sqm:10` | Area | 4 |
| `liter:2` | Volume | 3 |

- **Then** 각 경우 출력 단위 집합이 해당 카테고리 **전체**와 일치

---

### AC-04 — 입력 형식 검증

| 입력 | 기대 오류 |
|------|-----------|
| `` (빈 문자열) | E004 |
| `   ` (공백만) | E004 |
| `meter` | E001 |
| `meter2.5` | E001 |
| `meter:` | E003 또는 E001 (값 없음 — 시스템은 일관된 코드 하나 선택) |
| `:2.5` | E001 또는 E002 |
| `meter:abc` | E003 |
| `cubit:1` | E002 |

---

### AC-05 — 결정성

- **Given** 임의의 유효 입력 10건
- **When** 각 입력을 동일 환경에서 **2회** 실행
- **Then** 두 실행의 출력(또는 오류 코드)이 **100% 일치**

---

### AC-06 — 오류 시 무출력

- **Given** E001~E004 중 하나가 발생하는 입력
- **When** 처리 완료
- **Then**
  - [ ] 변환 결과 줄 **0건**
  - [ ] 해당 E00x 코드 **1건**만 보고

---

### AC-07 — 출력 형식

- **Given** 유효 입력
- **When** 정상 출력
- **Then**
  - [ ] 모든 줄이 정규식 `^[a-z]+:-?[0-9]+(\.[0-9]+)?$` 에 부합 (단위명 + 콜론 + 숫자)
  - [ ] 입력 단위 줄의 값 = 입력값 (동일 단위)

---

### AC-08 — Temperature 정확성 (샘플)

| 입력 | 기대 포함 출력 (예) |
|------|---------------------|
| `celsius:0` | `fahrenheit:32`, `kelvin:273.15` (또는 동등 정밀도) |
| `celsius:100` | `fahrenheit:212` |

- **Then** 물리적으로 올바른 변환값 (허용 오차는 테스트 명세에서 정의)

---

### AC-09 — SSOT (요구사항 수준)

- **Given** 동일 카테고리 내 두 단위 A→B 변환
- **When** A→Base→B 경로와 직접 비교 가능한 기준값 존재
- **Then** 모든 변환 결과가 **동일 Base Unit 기준**으로 일관됨 (모순 없음)

---

## 10. 범위 외 (Out of Scope)

- GUI / 웹 인터페이스
- JSON / CSV / 표 형태 출력 선택 (후속 버전)
- 사용자 정의 단위 등록 (후속 버전)
- 설정 파일 외부화 (후속 버전)
- 다국어 오류 메시지 (본 PRD는 오류 **코드**만 정의)

## 11. 용어

| 용어 | 정의 |
|------|------|
| 카테고리 | Length, Weight, Temperature, Area, Volume 물리량 그룹 |
| Base Unit | 카테고리 내 변환 기준이 되는 단위 |
| 결정적(deterministic) | 동일 입력 → 항상 동일 출력 |
| SSOT | Single Source of Truth — 변환 계수·단위 정의의 단일 출처 |
